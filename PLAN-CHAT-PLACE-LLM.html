1. Mục tiêu & flow tổng quan

Mục tiêu: User chọn số ảnh (vd 3) → LLM đọc toàn bộ chat hiện tại → quyết định 3 vị trí phù hợp (message nào, prompt gì) → inject marker vào chat[i].mes → save → pipeline hiện tại tự gen ảnh tại đúng vị trí.
User click "Plan 3 images" (Generation tab) → engine.planChatImages(3, { signal }) → buildContext() toàn chat (scene window mở rộng) → LLM call type='chat_place' → parse JSON placements [{anchor, prompt, negative?, size?}] → resolve anchor → message index (lastIndexOf, fallback skip) → append marker vào chat[idx].mes (theo mode) → saveChat() + emit MESSAGE_UPDATED per message → marker-pipeline bắt marker → compile → queue → gen → slot render
Điểm mạnh: Toàn bộ phần gen ảnh (compile, queue, restore, slot UI) đã có sẵn. Chỉ cần thêm: 1 request type, 1 engine method, 1 placement resolver, 1 UI section, 1 settings block. Không đụng pipeline runtime.

2. Request type mới: chat_place

2.1 Output format — JSON placements

{
  "images": [
    {
      "anchor": "She smiled and closed the door",   // vài từ cuối của message đích
      "prompt": "1girl, silver hair, smiling, closing door, ...",
      "negative": "lowres, bad anatomy",             // optional
      "size": "832x1216"                             // optional, "WxH"
    }
  ]
}

2.2 System prompt (prompts.js — renderChatPlacePrompt)

You are an image placement planner for a roleplay chat.
Read the conversation and decide where to insert N images.

Rules:
- Choose the N most visually significant moments (actions, scene changes,
  emotional beats). Spread them across the conversation, not clustered.
- For each image, pick the message whose content it illustrates.
- "anchor" = the last 3-8 words of that message, copied VERBATIM from the
  chat (no paraphrase, no punctuation changes). The system uses it to find
  the message, so exactness matters.
- "prompt" = a danbooru-style image prompt for that moment, following the
  dialect rules below. Include the active characters and their appearance.
- "negative" = optional negative tags.
- "size" = optional "WxH" matching the scene (portrait for close-ups,
  landscape for wide shots).
- Never place two images on the same message.
- Reply with JSON only:
{"images":[{"anchor":"...","prompt":"...","negative":"...","size":"..."}]}

2.3 Request mapping

chat_place dùng chung API profile với image_gen (default: settings.llm.defaultApiProfileId). Không cần context profile riêng — context được build inline trong engine method.

3. Engine method: planChatImages()

src/llm/engine.js — thêm method

/**
 * LLM plans N image placements across the current chat.
 * @param {number} count - number of images to place (1..6)
 * @param {{ signal?: AbortSignal }} [opts]
 * @returns {Promise<{ placements: Array<{
 *   messageId: number, prompt: string, negative?: string,
 *   width?: number, height?: number
 * }>, method: string, elapsedMs: number }>}
 */
async function planChatImages(count, { signal } = {}) {
    const settings = getSettings();
    const ctx = getContext();
    const chat = Array.isArray(ctx.chat) ? ctx.chat : [];

    // 1. Build full-chat context (scene window = cả chat, clamp 2..40)
    const contextResult = buildContext({
        chat, settings,
        contextProfile: { sceneWindow: 40, scope: 'scene' },
        substituteParams,
        roster: typeof roster === 'function' ? roster() : (roster ?? {}),
    });

    // 2. Resolve dialect rules (giống rewrite())
    const configuredProfileKey = settings.generation?.profile || 'anima';
    const { profileKey } = resolveProfileKey(null, configuredProfileKey);
    const dialectKey = PROFILES[profileKey]?.dialect ?? 'anima';
    const dialectRules = DIALECT_RULES[dialectKey] ?? DIALECT_RULES.anima;

    // 3. System prompt + user prompt
    const systemPrompt = renderChatPlacePrompt({
        count, dialect_rules: dialectRules,
        character_cards: contextResult.charBlock,
        persona_block: contextResult.personaBlock,
    });
    const userPrompt = renderUserPrompt(
        `Plan ${count} image placements for this conversation:\n\n${contextResult.sceneText}`
    );

    // 4. LLM call (type='chat_place', mapping fallback image_gen)
    const mapping = resolveRequestMapping(settings, 'chat_place');
    const profileId = mapping.apiProfile?.id
        ?? resolveRequestMapping(settings, 'image_gen').apiProfile?.id
        ?? settings.llm?.defaultApiProfileId ?? '';
    const result = await client.request({
        type: 'chat_place', systemPrompt, userPrompt, profileId, signal,
    });

    // 5. Parse + validate
    const parsed = parseJsonLoose(result.text);
    const placements = validatePlacements(parsed, chat, count);
    return { placements, method: result.method, elapsedMs: result.elapsedMs };
}

3.1 validatePlacements() — pure helper (testable)

// src/llm/placements.js (NEW — pure, no ST deps)
export function validatePlacements(parsed, chat, count) {
    if (!parsed || !Array.isArray(parsed.images)) return [];
    const out = [];
    for (const img of parsed.images) {
        if (typeof img?.anchor !== 'string' || !img.anchor.trim()) continue;
        if (typeof img?.prompt !== 'string' || !img.prompt.trim()) continue;
        const messageId = resolveAnchor(chat, img.anchor);
        if (messageId === null) continue;          // anchor không khớp → skip
        if (out.some(p => p.messageId === messageId)) continue; // trùng message → skip
        const size = parseSize(img.size);          // "832x1216" → {width, height}
        out.push({
            messageId, prompt: img.prompt.trim(),
            negative: typeof img.negative === 'string' ? img.negative.trim() : '',
            ...(size ? { width: size.width, height: size.height } : {}),
        });
        if (out.length >= count) break;
    }
    return out;
}

// Anchor → message index: tìm message có mes chứa anchor ở CUỐI (lastIndexOf
// trong window cuối). Ưu tiên character messages nếu settings bật.
export function resolveAnchor(chat, anchor, { onlyCharacter = true } = {}) {
    const needle = anchor.trim().toLowerCase();
    if (!needle) return null;
    for (let i = chat.length - 1; i >= 0; i--) {
        const m = chat[i];
        if (!m || m.is_system) continue;
        if (onlyCharacter && m.role === 'user') continue;
        const body = (m.mes ?? m.content ?? '').toLowerCase();
        if (body.includes(needle)) return i;
    }
    return null;
}

// "832x1216" → {width:832, height:1216} | null
export function parseSize(text) {
    if (typeof text !== 'string') return null;
    const m = text.trim().toLowerCase().match(/^(\d{2,4})x(\d{2,4})$/);
    if (!m) return null;
    const width = Number(m[1]), height = Number(m[2]);
    return (width >= 64 && width <= 2048 && height >= 64 && height <= 2048)
        ? { width, height } : null;
}
Anchor matching — độ chính xác: LLM hay paraphrase. Giải pháp 3 lớp:
  1. Exact substring (body.includes(needle)) — ưu tiên.
  2. Normalized — strip punctuation, collapse whitespace, so sánh normalized cả 2 phía.
  3. Fuzzy — nếu không match, tìm message có overlap token cao nhất (Jaccard trên từ cuối). Ngưỡng ≥ 0.5.
Không match được → bỏ placement (không gen bừa). User thấy số ảnh thực tế < số yêu cầu → có thể retry.

4. Marker injection & save

4.1 Marker format theo mode

ModeMarkerLý do
direct image###{prompt}### Compile thẳng, không qua LLM rewrite. Prompt LLM viết giữ nguyên.
assist / full <ifimage>{prompt}</ifimage> Transform ở index.js:409 → marker final: true → KHÔNG bị rewrite lần 2. Prompt LLM viết giữ nguyên.
Quan trọng: Nếu dùng image### ở assist/full, pipeline sẽ gọi LLM rewrite lại → prompt đổi, mất ý đồ placement. Luôn dùng <ifimage> ở assist/full.

4.2 Injection helper (index.js)

// Append marker vào cuối message, giữ nguyên phần còn lại.
function appendMarkerToMessage(message, marker) {
    const sep = message.mes && !/\s$/.test(message.mes) ? '\n' : '';
    message.mes = `${message.mes ?? ''}${sep}${marker}`;
}

// Sau khi inject tất cả placements:
async function applyPlacements(placements, { signal } = {}) {
    const ctx = getContext();
    const chat = ctx.chat ?? [];
    const mode = settings.generation?.mode ?? 'direct';
    const tags = settings.generation ?? {};
    const startTag = tags.startTag ?? 'image###';
    const endTag = tags.endTag ?? '###';

    // 1. Inject markers (từ cuối lên đầu để index không dịch chuyển)
    const touched = new Set();
    for (const p of [...placements].reverse()) {
        const message = chat[p.messageId];
        if (!message || touched.has(p.messageId)) continue;
        const marker = mode === 'direct'
            ? `${startTag}${p.prompt}${endTag}`
            : `${p.prompt}`;
        appendMarkerToMessage(message, marker);
        touched.add(p.messageId);
    }

    // 2. Save + trigger render
    try { ctx.saveChat?.(); } catch (err) {
        console.warn('[IF Image] saveChat after placement failed:', err?.message ?? err);
    }
    for (const id of touched) {
        eventSource.emit(eventTypes.MESSAGE_UPDATED, id);
    }
    return touched.size;
}
Vì sao emit MESSAGE_UPDATED: events.js đã bind MESSAGE_UPDATED → processMessage → phát hiện marker mới → onMarker → pipeline. Không cần gọi pipeline trực tiếp. (Xem events.js:143)

5.1 Wiring (ui.js)

  • if_plan_run click → đọc count + charonly → gọi engine.planChatImages(count, { signal }) → gọi applyPlacements(placements) → hiện kết quả: "Placed 3 images at messages #4, #7, #10".
  • AbortController per run; chat switch → abort (giống pattern hiện tại).
  • if_plan_undo → xóa marker vừa inject (lưu snapshot chat[i].mes trước khi inject, restore + saveChat + emit MESSAGE_UPDATED).
  • Nếu placements.length === 0 → toastr warning "LLM couldn't find good positions; try again".
  • Nếu placements.length < count → toastr info "Placed X/Y images (some anchors didn't match)".
